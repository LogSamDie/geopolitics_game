# Geopoly

A single-player, browser-based conquest game in the spirit of Risk, built for the INF4001N
entrance exam. You pick a country, nine NPC countries are drawn at random, and the last player
holding all ten wins. Games are public to watch; only the logged-in owner can play.

## How to run

With Docker (the way it is deployed):

```sh
docker compose up --build
```

Open <http://localhost:8000>, sign up and start a game. MongoDB runs in its own container and
keeps its data in a named volume.

For development, run the database, the API and the frontend separately:

```sh
docker compose up mongo                                   # MongoDB on localhost:27017
cd backend && uv sync && uv run uvicorn app.main:app --reload   # API on :8000
cd frontend && npm install && npm run dev                 # Vite on :5173, proxies /api to :8000
```

Checks:

```sh
cd backend && uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run pytest
cd frontend && npm run check && npm run build
```

The API tests need MongoDB. Formatters: `uv run ruff format .` and `npm run format`.

Settings are the environment variables `MONGO_URL` (default `mongodb://localhost:27017`),
`MONGO_DB` (`geopolitics`) and `STATIC_DIR` (`static`, where the built frontend is served from).

### Editor

Open the repository root in VS Code and accept the recommended extensions (Svelte, Prettier,
Python, Ruff, mypy, Containers). `.vscode/settings.json` points Python tooling at
`backend/.venv` and `backend/tests`, and makes Ruff and Prettier format on save. Run
`uv sync` in `backend/` and `npm install` in `frontend/` first so the language servers find
their dependencies.

## Stack

- **Backend**: Python 3.13, FastAPI, PyMongo's async client, fully typed (mypy strict).
- **Frontend**: Svelte 5 with TypeScript, built by Vite, MapLibre GL JS for the board.
- **Database**: MongoDB, three collections: `users`, `sessions`, `games`.
- **Deployment**: one multi-stage Docker image that builds the frontend, then serves it from
  the API process.

## How it works

The server owns every rule and every dice roll. The browser only sends intents (reinforce,
transfer, attack, roll, roll to the end, stop, end turn) and the server replies with the **events** that
resulted, including the NPC turns it simulated right after. Each event carries the countries
that changed and the turn as it then stood, so the browser never re-implements any rules. It
folds the events it has been shown into a board, and reveals new events one at a time with a
pause, which is what makes battles and NPC decisions visible as they happen. Fast-forward
shortens the pause, and the replay slider of a finished game simply moves the fold back.

- `backend/app/engine.py`: the rules, pure Python, no web or database code.
- `backend/app/npc.py`: the NPC strategy. It computes the exact probability of winning an attack
  from the dice rules, attacks the target with the best expected gain among those it has at least
  even odds against, withdraws when the odds drop below a quarter, puts its reinforcements on its
  largest army, and moves half of the attacking army into a country it conquers. Every decision
  is logged with a one-line reason.
- `backend/app/games.py` and `auth.py`: the HTTP API. A game document stores the current state
  plus the full event log; a version number stops two simultaneous requests from both applying.
- `frontend/src/lib/playback.svelte.ts`: the fold over events that the UI renders from.
- `frontend/src/lib/Map.svelte`: the board. Country borders come from Natural Earth and ship
  with the app, so there is no external tile server. Every country in the game has a tag with
  its soldier count (and its name, except on phones). The list beside the map always shows all ten
  countries with their counts, since tags can overlap, and countries can be picked from it. The human player is
  always red.

Country data is generated by `scripts/build_countries.py`, which downloads the population table
from worldometers.info (the source the assignment names) and the 1:50m country borders from
Natural Earth, joins them by name, and writes `backend/app/countries.json` and
`frontend/public/world.geojson`.

## Rules and assumptions

The rules follow the assignment. Where it leaves a gap we chose:

- The soldiers gained for a conquest (max of 2 and half the country's value) are placed in the
  conquered country. The attacker may then move more soldiers into it, or anywhere else, before
  ending the turn.
- Stopping an attack ends the turn immediately, as the assignment says. An attack that ends by
  itself (conquest, or the attacker is down to 1 soldier) leaves the player in their turn, where
  they can still move soldiers before ending it.
- Reinforcements are placed first; transfers and the attack follow. Since placing only adds
  soldiers, this never limits what a player can do with a turn.
- A player eliminated from the game is skipped. If the human player is eliminated the NPCs play on
  until one of them holds all ten countries.
- Dice are paired in the order rolled (die 1 against die 1), the higher roll wins, a tie kills
  nobody, and the number of dice is the smaller of the defender's soldiers and the attacker's
  soldiers minus one. Any country may attack any other.
